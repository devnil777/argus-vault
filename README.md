# argus-vault — резервные копии через RAR

Команда запуска: `backuper`.

Версия 0.2.0. Только Windows.

Консольная утилита, которая строит резервные копии через RAR по схеме «полная копия — эпоха» плюс цепочка инкрементальных копий (diff). Архивы — обычные RAR-файлы и самодостаточны: для восстановления данных не нужен backuper, достаточно RAR-архиватора.

## Возможности

- Полные и инкрементальные копии внутри одной эпохи, сравнение по пути + размеру + времени изменения.
- Каждый архив сам описывает себя: рядом лежат хэш и журнал, внутри архива — манифест, снимок файлов, списки удалений, конфиг.
- Проверка целостности архивов и восстановление через recovery record (5%).
- Опциональное шифрование: случайный пароль архива, упакованный открытым ключом получателя, подпись манифеста.
- Планировщик Windows Task Scheduler.
- Самодиагностика RAR.

## Зачем

- Надёжность важнее скорости: любая ошибка RAR — ошибка запуска, временный файл переименовывается только после успешного создания.
- Восстановление возможно без backuper: обычный RAR, файлы читаются как есть.
- Конфиг фиксируется при создании полной копии и дальше берётся из архива — цепочка не зависит от внешних файлов.

## Требования

- Windows.
- Консольный `Rar.exe` версии 7.x. Должен находиться рядом со скриптом/программой или в PATH, либо указываться через `--rar`.
- Поддерживаются русская и английская сборки консольного Rar.exe; язык вывода RAR не имеет значения (подписи канонизируются).
- Вариант Python: Python 3.11+, пакеты `pyyaml`, `cryptography`.

## Быстрый старт

Без шифрования:

```
backuper init D:\Backups\Docs --source D:\Data\Documents   # создать job и шаблон конфига
backuper full  D:\Backups\Docs                             # полная копия, новая эпоха
backuper diff  D:\Backups\Docs                             # инкрементальная копия
backuper list  D:\Backups\Docs                             # список эпох и архивов
backuper verify D:\Backups\Docs --chain                    # проверка всей цепочки
```

С шифрованием:

```
backuper init D:\Backups\Docs --source D:\Data\Documents --generate-keys  # + пары ключей
backuper full  D:\Backups\Docs                                            # полная копия с шифрованием
backuper diff  D:\Backups\Docs                                            # инкрементальная копия
backuper password D:\Backups\Docs\2026-11-09\2026-11-09_031500_full.rar   # вывести пароль архива для распаковки
```

`keygen` создаёт пары ключей; приватные ключи храните отдельно и безопасно. Планирование: `backuper schedule add D:\Backups\Docs diff --daily 03:00`.

## Конфиг

Пример `config.yaml`:

```
source: 'D:\Data\Documents'
exclude_extensions: ['.tmp', '.bak']
exclude_dirs: ['node_modules', 'D:\Data\Documents\Cache']
lock_check_extensions: ['.pst', '.ost']
compression: 3
```

Поля:

- `source` — один абсолютный каталог, обязательный.
- `exclude_extensions` — расширения, которые не попадут в копию (регистр не важен).
- `exclude_dirs` — имена каталогов или абсолютные пути, которые исключаются.
- `lock_check_extensions` — файлы с этими расширениями проверяются на блокировку перед архивацией.
- `compression` — уровень сжатия RAR 0–5, по умолчанию 3 (0 — без сжатия, только хранение; 5 — максимальное сжатие, медленнее).
- `recipient_public_key` — открытый ключ получателя для шифрования (необязательно, только вместе с ключом подписи).

Неизвестные ключи отклоняются. Конфиг становится частью полной копии и дальше берётся из архива.

## Структура каталога job

```
D:\Backups\Docs\
  config.yaml
  .lock
  recipient_private.pem        # при шифровании
  signing_private.pem
  signing_public.pem
  2026-11-09\                 # эпоха (дата начала)
    2026-11-09_031500_full.rar
    2026-11-09_031500_full.rar.sha256
    2026-11-09_031500_full.rar.log
    2026-11-09_092000_diff.rar
    2026-11-09_092000_diff.rar.sha256
    2026-11-09_092000_diff_failed.log
    2026-11-09_092000_diff_nothing.log
```

- Каталог эпохи назван по дате начала (YYYY-MM-DD); внутри — полная копия, затем инкрементальные.
- Имя архива: `<дата>_<время>_<full|diff>.rar`, сортируется в Explorer.
- Рядом с архивом: `.sha256` (проверка одной командой `certutil -hashfile`), `.log` (журнал RAR), `_failed.log` при сбое, `_nothing.log` при отсутствии изменений.
- `.lock` — блокировка одной job средствами ОС.
- Приватные ключи лежат рядом с конфигом и никогда не попадают в архив.
- Внутри каждого архива каталог `.backup/`: `manifest.json` (+`.sig`), `files.json` (снимок всех файлов и пустых каталогов), `delete_files.txt` и `delete_dirs.txt` (только в diff), `config.yaml`.
- Старые эпохи удаляются вручную.

## Восстановление без backuper

```
rar x 2026-11-09_031500_full.rar D:\Restore\
rar x 2026-11-09_092000_diff.rar D:\Restore\
```

- Распаковывайте полную копию, затем инкрементальные по порядку.
- Удалённые файлы и каталоги — по `delete_files.txt`/`delete_dirs.txt` внутри diff.
- Целостность: `certutil -hashfile <архив> SHA256` и сравнение с `.sha256`.
- Зашифрованные архивы: пароль получайте через `backuper password <архив>` (требуется приватный ключ).

## Проверка и диагностика

- `backuper verify <job> [--chain] [--fix]` — проверка последнего архива эпохи или всей цепочки; `--fix` чинит через recovery record и пересоздаёт отклонившиеся сопроводительные файлы.
- `backuper diagnose` — проверка совместимости с установленной версией Rar (пути, блокировки, прогресс и т.д.).

## Шифрование (необязательно)

- Включается ключами `recipient_public_key` в конфиге и файлом `signing_public.pem`; приватные ключи — `recipient_private.pem`, `signing_private.pem`.
- Каждый архив получает случайный пароль, который упаковывается открытым ключом получателя; манифест подписывается.
- `backuper password <архив>` печатает пароль (64 hex-символа) в stdout.
- Потеря `recipient_private.pem` = потеря доступа ко всем архивам, сделанным этим ключом. Храните копию отдельно.
- Шифрование не скрывает список файлов: имена, размеры, `.backup/*` остаются открытыми.
- Смена ключей влияет только на новые архивы; старые остаются расшифровываемыми старым ключом.

## Планировщик

- `backuper schedule add <job> {diff|full} (--daily HH:MM | --weekly DAYS --at HH:MM | --interval MINUTES)`
- `backuper schedule remove <job>` / `backuper schedule show [<job>]`
- Задачи работают только пока пользователь залогинен; вывод пишется в `.schedule.log`.
- Автоопределение программы: exe или `python -m backuper`.

## Коды возврата

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | проверка перед запуском: RAR не найден, нет источника, плохая раскладка каталога |
| 2 | RAR завершился с ошибкой или диагностика не пройдена |
| 3 | проверка целостности не пройдена |
| 4 | job заблокирована другим процессом |
| 5 | ошибка конфига или командной строки |
| 6 | нечего копировать (diff без изменений) |
| 130 | прервано (Ctrl+C) |

## Ограничения

- ACL/права NTFS не сохраняются.
- Symlink и junction пропускаются.
- Изменения только в ADS не детектируются (хотя ADS сохраняются).
- Переименование считается как удаление + добавление.
- Файл с теми же размером и временем изменения может быть пропущен.
- Один источник на job; старые эпохи не удаляются автоматически.
